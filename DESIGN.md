# Design System: Harikesh Mishra Portfolio

## 1. Overview

**Creative North Star: "The Quiet Engineering Notebook"**

The portfolio is a minimal, proof-led introduction to a software engineer and a home for deep technical writing. The interface behaves like a dependable reading surface: one narrow column, direct navigation, generous spacing, and evidence before ornament.

Home follows the text-first school of Emil Kowalski's and Prasanjit Dey's sites: everything at body size, hierarchy from weight and color, 128px between sections, and rows that show a soft surface on hover. The one richer element, the GitHub contribution graph, lives on About.

It is rigorous, pragmatic, and candid. Recruiters can scan tangible outcomes quickly; fellow engineers can settle into substantial articles without visual noise.

**Key Characteristics:**
- A `42rem` single-column layout across portfolio, articles index, and article pages.
- Explicit light and dark themes using the same semantic tokens.
- Inter for all interface text, prose, and headings; JetBrains Mono only for code.
- Phosphor provides the single interface-icon language across navigation, downloads, disclosures, and article controls.
- Terracotta is reduced to focus rings, selection, and the reading-progress line. Links, markers, and inline code are neutral.

## 2. Colors

The neutrals are true greyscale at chroma `0`, so terracotta is the only hue and it appears only on interaction state. All components consume semantic variables so light and dark modes switch together.

### Light Theme
- **Surface** (`oklch(0.994 0 0)`): reading background.
- **Foreground** (`oklch(0.42 0 0)`): body text and prose.
- **Strong Foreground** (`oklch(0.205 0 0)`): titles, headings, and key navigation.
- **Muted** (`oklch(0.53 0 0)`): descriptions, metadata, and secondary context.
- **Divider** (`oklch(0.92 0 0)`): hairline borders and the rare rule.
- **Hover** (`oklch(0.965 0 0)`): hover-row, chip, and inline-code surface.
- **TOC Track** (`oklch(0.62 0 0)`): the floating rail's readable inactive state.

### Dark Theme
- **Surface** (`oklch(0.145 0 0)`): near-black reading background.
- **Foreground** (`oklch(0.78 0 0)`): body text and prose.
- **Strong Foreground** (`oklch(0.97 0 0)`): titles, headings, and key navigation.
- **Muted** (`oklch(0.63 0 0)`): descriptions, metadata, and secondary context.
- **Divider** (`oklch(0.27 0 0)`): quiet structural separation.
- **Hover** (`oklch(0.205 0 0)`): hover-row, chip, and inline-code surface.
- **TOC Track** (`oklch(0.53 0 0)`): the floating rail's readable inactive state.

**The Neutral Rule.** Neutrals stay at chroma `0`. The contribution graph uses five opacity steps of Strong Foreground rather than a green ramp. The sanctioned exceptions are the availability dot (`--status-open`, a quiet green), the guide-preview task blue (`--scene-task`), the sketch marks (a warm graphite `--sketch-ink`, a yellow highlighter `--sketch-marker` and the pink pen `--sketch-pen-stroke` / `--sketch-pen` of the "New" tag) and the home intro keywords: three hue tokens (`--keyword-ship` blue, `--keyword-learn` magenta, `--keyword-backend` green), each tuned to at least 5.5:1 contrast in light and 8.6:1 in dark, appearing only while the pointer or focus is inside that paragraph.

### Accent
- **Terracotta** (`oklch(0.51 0.13 32)` light; `oklch(0.72 0.13 32)` dark): focus rings, text selection, and the reading-progress line.

**The Signal Rule.** Terracotta marks interaction state only. Links use a 30% Strong Foreground underline that darkens on hover; list markers are muted; inline code is a neutral bordered pill.

## 3. Typography

**Body and Headings:** Inter (optical sizing, 400–600, true italics), ui-sans-serif, system-ui, sans-serif
**Code:** JetBrains Mono, ui-monospace, monospace

### Hierarchy
- **Page Title:** 22px semibold, `-0.02em` tracking (Articles, About, Resume, Contact, Privacy). Article titles are 20px semibold with `-0.015em` tracking.
- **Home Intro:** 16px regular. The `h1` line is Strong Foreground; the paragraphs after it are Muted with Strong Foreground underlined links.
- **Section Heading:** 16px medium Strong Foreground, sentence case (`SectionHeading`). No uppercase mono labels.
- **Row Title:** 16px regular Strong Foreground; the description below is 16px regular Muted.
- **Metadata:** 13px Muted with tabular numerals.
- **Body:** 16px Inter at 1.65 line height, `-0.006em` tracking.
- **Guide Prose:** 16px Inter at 1.75 line height (28px). Top-level paragraphs are separated by one line (28px), following Emil Kowalski's rhythm.
- **Guide Chapter:** 18px semibold with `-0.014em` tracking, 56px above and 20px below.
- **Guide Subsection:** 16px semibold with `-0.01em` tracking, 36px above and 12px below.

**The Reading Rule.** Everything stays near body size. Hierarchy comes from weight, color, and generous spacing (64px between home sections, 128px from `sm`), not from display type.

Build-time presentation gives introductory context and exercises explicit roles with italic body text and 1.6em group margins, without quotation bars or generated quotes. Actual quotations retain italics and semantic markup, but left borders are removed from every article blockquote. Rules immediately before chapter headings are omitted; other thematic breaks remain. Structural labels become authored headings at the appropriate depth, using the existing type scale and preserving wording.

**Emphasis in guides.** `em` and `i` inside `.guide-content` switch to the system serif italic (`ui-serif, Georgia`) at 1.05em, so emphasis reads as voice rather than volume. No font is downloaded for it.

## 4. Elevation

### Article Media

Explicit output and ASCII-diagram fences use Expressive Code's native titles, without restyling its internals. Tables retain their semantic table layout inside a keyboard-focusable scroll region, with restrained rules and preserved column alignment. Standalone images use figures with authored captions in 14px muted text at 1.6 leading. Local PNG dimensions reserve the image's aspect ratio before loading. These treatments preserve the existing reading type scale and italic notes.

The system is flat. Whitespace establishes priority and hairline borders frame the few surfaces that need edges: the back and download chips, the Stack list, and code frames. There are no shadows, gradients, or glass effects. Expressive Code frames use a 12px radius and `frameBoxShadowCssValue: none` through `styleOverrides` in `vite.config.ts`.

Code is rendered by Expressive Code with the Pierre light and dark syntax themes (`@pierre/theme`, wired in `vite.config.ts`). Fenced blocks include a copy control and respond to the page's `data-theme` value. Inline code is a compact neutral pill with a hairline border and no generated backticks.

## 5. Components

### Navigation
- **Shape:** Identity mode is a 40px avatar beside the name (16px medium, Strong Foreground, 24px leading) over the role (16px medium, Muted, 16px leading), so the avatar matches the two-line block exactly. It sits 96px from the top, with the theme toggle on the right. There is no header nav. Article pages swap to a breadcrumb where the same avatar shrinks to 24px. Geometry constants in `Header.tsx`: identity height 136px, avatar at y 96px; breadcrumb height 76px, avatar at y 26px. The toggle sits at y 94px in the identity row from `sm` and at y 16px everywhere else, as Tailwind `translate` classes with a 300ms `pageEase` transition, so on phones it stays put when an article opens. Switching theme runs a View Transition with the default crossfade turned off: the new theme grows as a circle from the toggle's center until it covers the farthest corner (520ms on `cubic-bezier(0.22, 1, 0.36, 1)`, `themeRevealTiming` in `motion.ts`). Reduced motion, or a browser without View Transitions, switches instantly.
- **Site navigation:** From `sm`, Articles, About and Resume sit in the identity row as 13px Muted links that turn Strong on hover or when active, followed by search and ending before the theme toggle. Phones have no header links: the header is only the avatar, the name and the theme toggle, and the bottom dock carries the pages. Their identity row moves up to the toggle's line (avatar at 18px, centred on the toggle at 38px, header 58px tall, versus 96px and 136px from `sm`). The header's vertical geometry (height, avatar offset, toggle offset) lives in per-breakpoint Tailwind classes, so the morph stays constants-based with no measuring; Motion animates only the avatar's scale, and the offsets move on CSS `translate` with the morph's timing. Article pages use the breadcrumb instead, where the avatar also centres on 38px, so on phones the morph only shrinks the avatar and shifts it 8px. On articles, the phone table-of-contents pill steps aside (fades and drops 0.75rem, inert and hidden from assistive tech) while the site footer is on screen and the sheet is closed, and returns when the reader scrolls back up. The footer keeps the full site nav.
- **Phone site dock:** Below `sm`, every page except articles gets `SiteDock`: a 44px pill centred above the bottom safe area, on the TOC pill's surface (`--toc-surface`, `--toc-border`, squircle, shadow), with "Search" (opens the command palette) and a menu button. The menu opens a 176px popover above the pill with Home, Articles, About, Resume and Contact as 44px rows, the current page Strong (`aria-current`). It pops up on `siteDockMenuSpring` from 96% scale and 6px down, and leaves on `siteDockMenuExitTween` (about 65% of its entry, ease-in); reduced motion only fades. A transparent layer behind the open menu takes the outside tap, so closing it never also opens a link underneath. Escape closes it and returns focus to the menu button. It is the phones' navigation, so it shows from the top of the page. It shares the TOC pill's rules through `useDockTuck`: hidden while the reader scrolls down (past the first 160px) and while the footer is on screen, back the moment they scroll up, and never hidden while it has focus or its menu is open. Hidden means faded, dropped 0.75rem, inert and hidden from assistive tech.
- **Site links in the TOC sheet:** Articles have no dock. Instead, the open table-of-contents sheet ends with a hairline and a "Site" nav row: Home, Articles, About and Resume as 13px links with 44px targets, and a search button that closes the sheet and then opens the command palette. The row is measured with the list, so the sheet's content-measured size includes it, and the focus trap covers it.
- **Resume Asset:** Resume links use a content-hashed public URL while downloads preserve the clean `Harikesh_Mishra_Resume.pdf` filename.
- **Theme Control:** Minimum 44px target; persists explicit `light` or `dark` preference in local storage.
- **Focus:** 3px terracotta outline with 3px offset.

### Home

- **Mumbai pond:** A generative koi pond above the intro (`MumbaiPond`, garden mode of `src/components/pond/`), 2:1 on phones and 11:4 from `sm`. On phones it runs edge to edge like a photo in a feed, square-cornered with only its top and bottom feathered; from `sm` it sits on the text column with rounded corners and all four edges feathered. Its light follows the current hour in Mumbai (`pond-daylight.ts`, unit-tested): teal by day, rose at dawn, golden at dusk, and deep blue at night with a moon glow, a wavering reflection and slower koi; the dark theme softens daylight to 66% so it never glares but still reads as day. Until WebGL draws, the box shows a CSS gradient for the same hour, never a fixed daytime teal: an inline script in the root route interpolates `placeholderStops` from Mumbai's clock before first paint and sets the pond's water colours, the bulbul's sky (sampled from its frames at night, dawn, day and dusk) and the 404's open sky for both themes. Night stays a readable blue rather than near-black, so the koi and lily pads remain visible at every hour. A WebGL2 renderer (`pond-gpu.ts`) draws the water, floor and koi. A ripple simulation runs on the GPU: a tap drops a ripple, every tail beat drops a small one so swimming koi leave wakes, and a pointer trailing through the water stirs it. The floor (sand and smooth stones) is refracted through the moving surface and lit by caustics that the ripples bend and focus, with glints on ripple crests and, at night, a moon glow whose reflection breaks into glitter. Koi (kohaku, ogon, sanke, tancho, showa, yamabuki; `pond-fish.ts`) are ribbon meshes drawn from above to a koi's proportions: a blunt rounded head with gill seams, eyes on top, a mouth and two short barbels, shoulders that swell behind the head, and a long taper to the wrist of the tail. Broad pectoral fins flare to brake or hover and fold flat for a sprint, the inner one opening wider in a turn; a thin dorsal ridge runs down the back; the tail is a soft forked veil that trails the stroke and swings wide of a turn. Every koi is lit from the pond's one light, up and to the left like the stones, so the flank toward it is bright and the far one in shade whichever way the koi faces, with a wet highlight where the back turns to the light. Scales show as staggered rows wherever one is more than a few pixels wide. Markings end on whole scales there, the stepped edge a real pattern has, and have crisp, uneven edges elsewhere. The ogon and yamabuki carry a metallic sheen, a ripple runs out along the tail like silk, and fin rays fade into the membrane at phone sizes instead of shimmering. They swim the way fish do: a wave runs from head to tail and grows as it goes, so the head stays nearly still and the tail sweeps widest, and a koi at ease takes a few tail beats and then glides with its body straight (`poseOf` and `steer`, unit-tested). A koi turns in an arc, not on a pin: its turn rate is its speed over its tightest arc (0.34 body lengths) plus a slow pivot on its fins, capped at 2.4 radians a second, and it builds and fades. So a koi sweeps round instead of spinning or curling up like a comma, and it slows for a target behind it or inside its turning circle. A roaming koi weighs six spots and takes the one that needs the least turning and has the fewest koi near it, so the six spread over the pond. Each spine joint bends at most 0.28 radians, so even a startled koi never folds. Now and then one rests low in the water with its fins out, more often at night, or trails another for a while. Each koi has a depth: deeper ones are drawn first, take on more of the water's colour and cast a tighter shadow, two that cross move to different depths so one passes under the other, and all of them rise to food. Koi keep apart through an eased drift, never by having their heads moved, and the drawing order changes only while two koi are apart, so a crowd neither jitters nor pops. The six are different sizes, one large and one young, none longer than 17% of the pond's width, and a pond narrower than 480px holds five. At night moonlight puts a cool sheen along every back, so the black showa stays readable. Reeds sway at two corners and lily pads drift slowly with the koi passing beneath them (`pond-decor.ts`); night and the dark theme dim everything drawn above the water. Without WebGL2 the older WebGL1 caustics shader (`pond-water.ts`) and the 2D koi take over. Koi gather in a loose ring near a mouse or pen. A tap drops food: koi right under the splash dart away for a moment, then every koi in reach shares the pellets out, rises, keeps its pace up, crowds in closer than koi usually swim, opens its mouth and takes one in passing, leaving a small ring. Pellets are small lit beads that bob, each with a shadow on the floor. The caption says so ("The light follows my local time in Mumbai."); the live clock is left to the availability line and the footer, so Home shows it twice instead of three times. `?pond-hour=18.5` previews another hour. The event-loop version of the same engine lives in the event-loop guide as an island.
- **Makari Kund (parked):** `KundPond` is a finished alternative to the koi pond, not on any page. It is Harikesh's photo of the temple tank at Bijethua, 2:1 at every width, set on a 3D model of the tank so every pixel stays a real one from the photo while code moves and relights it: recomputed reflections that wind and taps bend, low evening sun with wall shadows, lamps and diyas lighting the nearest stone at night, swaying trees, birds and fireflies, and a sky matte that keeps the trees free of halos at dusk and night.
- **Bulbul (preview):** `BulbulScene` is an alternative to the koi pond on Home with `?scene=bulbul`. It was the 404's scene until the open sky took that page, and its code is kept whole, including the fly-in arrival the 404 used (`birdArrival="fly-in"` on `Pond`: the bough sways empty for about a second, then the bulbul flies in, lands and sings, and at night it crosses the moon, looks around for 2.5s and tucks in to sleep). A red-vented bulbul ("bulbul" is the nightingale of Urdu and Persian poetry) perches on a peepal bough against the sky, 2:1 at every width. It is a silhouette study, shot as a long lens would shoot into the light: the far trees melt into a soft green blur with bokeh where the sun glints through, two leaves near the lens are far out of focus, and bird and wood are near-black with a hairline rim where their edges face the light and a warm glow through thin feathers. Because a silhouette lives on its outline, the bird's body is one traced contour (a smooth closed curve through hand-placed points, to the bulbul's proportions: leaning forward about fifty degrees, breast out, belly low over the feet, the back one line from nape to rump), with the head, a short shaggy crest, a short straight beak, the folded wingtip and a long tail with slits between its feathers laid over it; only hints of colour show, the red vent and the tail's pale tip. The bough is a thick branch entering from the right with a limb forking up and arching over the scene, curved twigs that split again, and a few dead stubs; its bark is knobbly, furrowed and patched with lichen. Peepal leaves hang from the twigs on long stalks, each following its twig's line partly and drooping the rest of the way: hearts with a long drip tip, a midrib and arching side veins, with smaller coppery-pink new growth at the twig tips. They tremble as peepal does, swinging like pendulums and twisting so they foreshorten and flip their paler undersides into view, glowing through the light and darker where two overlap. Thin streaks of cirrus catch the sun and the low sky burns warm at dusk. The air carries motes of dust that flare when they cross the light, faint god rays fan from the sun, and now and then a few small birds cross the far sky. The bird behaves like one: its head moves in quick snaps with still pauses, never smooth turns; it breathes; it flicks its tail up often; and every couple of seconds it does one thing from a small repertoire: a burst of tail flicks, preening with small nibbles at its breast, a rouse (feathers fluffed out, shaken, smoothed), a wing stretch, a shuffle along the branch, turning around, or a song by day. Tap it and it sings aloud: a synthesized red-vented bulbul call (`bird-song.ts`, Web Audio, no files), one of four phrases birders write as "be-care-ful", "ginger-beer", "pick-pick-pikee" and "sweet-chee-wee", each three liquid whistled notes between 2 and 3 kHz with a chip, a slur and a slight warble, pitched and paced a little differently every time; the head lifts, the beak opens wide and the throat swells on each note. It only sounds after a reader taps the bird (the audio context starts inside that tap, so nothing plays on load), and the songs it sings on its own by day are silent. tap the branch and it hops there, turning first if it faces away, and the branch dips under it on a damped spring; three quick taps startle it into flight, and every minute or two it flies off on its own and comes back. With a mouse it glances at the pointer now and then. The light follows Mumbai's hour: a pink dawn, a high hazy sun, a golden hour with the sun low behind the leaves, and at night the moon, stars and fireflies while the bulbul sleeps fluffed with its head tucked in. At night a tap on the bird wakes it: it unfluffs and shakes out over 0.8s, then sings (the phrase is scheduled inside the tap with that delay, so the browser lets it play) and stays awake a few seconds before tucking in again; a tap anywhere else only wakes it to look around. The night sky is Mumbai's: the moon rises on the left like the sun and arcs to the right, a shaded disc with darker seas, a wide halo and silver edges on nearby cloud; a warm sodium glow and haze lie low over the treeline and wash out the faintest stars, with a sparse layer of brighter, softly glowing ones above; moonlight puts a cool edge on the bird, leaves and bough so the sleeping silhouette reads; and warm fireflies drift low among the leaves. One wind is shared by bough, leaves and feathers. A filmic tone curve, grain and a vignette finish the frame. Under reduced motion it starts paused on a still frame, and a tap still answers.

- **Event-loop figures (in the guides):** `EventLoopFigure` is an island that takes `example`, naming an entry in `src/components/event-loop/examples.ts`. Each example runs a guide's own code, line for line, through a small deterministic simulator (`src/lib/event-loop-sim.ts`, unit tested): one call stack, a microtask queue, a task queue and timers in web APIs, one visible event per tick, following the guides' rule (finish the current job, drain every microtask, then take one task). Time is kept apart from ticks: by default every tick costs one unit, but an example can make ordinary statements free so that only real work and waiting move the clock, and timers count down in that time alongside JavaScript. Four examples exist. `tasks-and-microtasks` sits in the event-loop guide after "Tasks and microtasks are not the same". `blocked-timer` sits in "setTimeout Has Trust Issues" after the blocked-stack example: one unit is one second, the timer finishes at 5s while the loop holds the stack, and its callback starts at 10s, as the guide says. `var-loop` and `let-loop` sit together in the closures guide after Example 4, placed with `compare="let-loop"`: a var | let toggle in the code bar (inverted Strong when pressed) swaps the examples, keeps focus on the toggle, and resumes playing if the reader had started. One unit is one second. The simulator models scopes for these: `bind` and `set` instructions write bindings into named environments, a `log` can read a binding through the running callback's closure, and every step carries the guide's own explanation as its caption, with code words set in mono. In place of the trace, a fixed-height "bindings" panel lists one row per environment ("x environment  i = 6", or "iteration 3  i = 3") followed by numbered blue chips for the callbacks that close over it; a write brings the new value in from 4px above in terracotta, the row being read or written gets a faint wash, and the running callback's chip fills. These examples hide the add-work buttons. Queues show two pills; more wait out of sight behind a "+N more" count in the box header. The style was studied from about twenty PlanetScale embeds. Layout: the diagram across the full width, a caption, then the source beside the console and a "what held the stack" trace, then the controls and a figcaption, in one hairline-divided frame. The source highlights the line being executed in the job's colour and tints the lines of whichever callback is running. The console prints each log in its job's colour with a muted stamp (seconds for timer examples, otherwise the tick) and scrolls to the newest line. The trace draws one lane each for script, microtask and task, with a dashed line at every switch. Controls are monospace: Play/Pause (primary), ‹ Back, Step ›, Restart ↺, a 0.5× / 1× / 2× segmented speed control, and colour-coded "+ setTimeout" and "+ microtask" buttons that add work (and play). Keyboard: ← and → step, Space plays or pauses (a legend shows on fine pointers). Back walks through up to 400 earlier states, including added work. The figure waits behind a start button with the diagram dimmed to 55%, pauses when it scrolls out of view, ticks every 1.3s at 1× (`eventLoopBeatMs`), and keeps working under reduced motion with movement removed.
- **Guide figures (in the guides):** `GuideFigure` is an island that takes `figure`, naming an entry in `src/components/guide-figures/GuideFigure.tsx`. Each one replaces one of the guides' text diagrams (fenced box-drawing art) with a drawn, stepped figure in the event-loop figures' frame and language: a stage on the dot grid, a caption, monospace controls (Play/Pause/Replay, ‹ Back, Step ›, Overview, a step count), a figcaption, and the diagram as a screen-reader list. The overview (step 0) shows the whole diagram at rest, so the figure reads like the text diagram it replaced before anyone presses Play. Each step lights some boxes and wires in one tone (Strong, terracotta or blue), dims the rest to 38%, and its caption uses the guide's own wording with code in mono. Lit wires flow and carry a pulse (`guideFigurePulseMs`, 1.4s); playing advances every 2.2s (`guideFigureBeatMs`). ← → step and Space plays; figures pause when scrolled away; reduced motion drops the pulse, flow and transitions. Drawings use a 360-unit viewBox capped at 30rem wide, with text stepped up on phones. The kit (`kit.tsx`) provides the frame, the stepper and a declarative `Flow` of boxes (plain, ghost, group and readout) and wires with arrowheads. Bespoke figures cover what boxes cannot: the parser (source line, scanner cursor, token chips, tree), the generational heap (objects glide between young, old and reclaimed as collections run), the CPU scheduler (to-completion versus time slices, with a toggle), the engine journey (a numbered rail beside what `add` looks like at each stage, with labelled simplified bytecode and pseudo machine code), the call stack (frames beside the program and its console) and the process address space. The Node.js layers figure lets readers follow `setTimeout`, `fs.readFile` or `JSON.parse` through Node. The scope figures (`scope.tsx`) add a scope-chain lookup: environment cards joined by "outer" arrows, a search token in the left gutter that checks each card in turn (blue while checking, dimmed with "no a" once passed, terracotta with the binding lit when found, a ReferenceError row when the chain runs out), the program beside it with the reading line lit, a picker when a figure has several names to look up, "not searched" for scopes a lookup never enters, and a dashed side card for a scope that is not on the chain. Clicks route through the same navigation as the table of contents; keyboard and screen-reader users keep the table of contents as the semantic route, and heading names stay clean. Table-of-contents activation pushes a shareable same-route hash entry, repeated activation replaces it, back/forward re-traverses headings, and returning to the hashless entry restores the captured pre-click scroll position.
- **Desktop Table of Contents:** At `xl` and above, a column adapted from Rare UI's Hook Sidebar sits in the right gutter, 2rem from the text column and clear of the header: "On this page", then every `##` section title (13px, Muted, two lines at most, Strong when active). A terracotta dashed rail runs from the top of the list down to the section being read and turns into it with a small rounded hook; while the pointer or keyboard focus rests on another row, a faint dashed rail previews the way there. Both rails travel on Rare's spring (stiffness 420, damping 34, mass 0.7, `tocHookSpring`) and fade in 200ms; reduced motion moves them instantly. A list taller than the window scrolls on its own with edge fades and keeps the active row in view. Rows are semantic hash anchors that push history, `aria-current="location"` marks the active one, Escape blurs, and the retained route-safe lifecycle and the single scrollspy are unchanged.
- **Mobile Table of Contents:** Below `xl`, a content-measured text pill (it stays tucked until the scrollspy's first pass, so it enters already naming the current section, and it reads "Table of contents" above the first listed section, such as a "Read this first" intro) stays near 32px tall within the viewport, with a separate invisible 44px trigger target. Opening expands that same surface upward and in place into a content-measured `w-max` menu capped by the viewport and `min(64dvh, 520px)`, with a 26px squircle radius. The surface is opaque (`--toc-surface`): a 98% alpha rendered visibly see-through over article text in Chrome, which made the list hard to scan. Rare's 60%-border token remains. A transparent outside-click layer dismisses it without visible dimming. Neutral 30px semantic anchor rows retain safe-area padding, focus trapping, background inerting, native list momentum, Escape, focus return, optional bounded drag dismissal, and reduced-motion parity. Source-like surface, label, and row timing is retained, with the long-list stagger bounded at 0.4s.
- **Reading Progress:** A 2px terracotta top hairline uses CSS scroll-driven animation where supported; it is absent for reduced-motion preferences.
- **Diagrams:** Images from `/diagrams/` keep their original reading size and end with a quiet `Open full diagram` text cue. The native modal makes the hand-drawn sketch the sole focal object on its white teaching surface, set against a dark scrim. Pointer activation fades the scrim over 160ms, then after a 40ms handoff brings the viewport-bounded sheet from 10px below at `0.985` scale through a 240ms transform spring with a fast 160ms opacity handoff. The 160ms close has no bounce. Keyboard and reduced-motion activation are instant. It locks background scrolling, closes through its visible control, Escape, or backdrop, and returns keyboard focus to the invoking diagram.
- **Islands:** Interactive demos sit in the prose as a rounded-xl bordered card on the surface color with 16px padding, followed by a centered 14px muted caption that tells the reader what to do ("Press Run to watch the order."). They render on the server, so the card is in place before JavaScript loads, and each hydrates independently. Demo buttons use `.chip-link`. Article figures load lazily with reserved dimensions.
- **Code:** Expressive Code frames retain their generated theme and copy behavior; local CSS only styles inline code. Programmatic heading navigation uses a three-frame settle loop with instant correction steps. The article tree deliberately avoids `content-visibility`: the corrected retry achieved exact anchors and a sub-700ms throttled task, but failed the unthrottled slow-frame gate.
- **Reading Stability:** The complete article body renders immediately and remains stationary during scrolling. Prose, headings, code, figures, lists, tables, and blockquotes have no reveal metadata, observers, or entrance animation; previous/next links use color-only hover feedback.

### Motion
- **Route and entry:** Navigated route wrappers become visible immediately after the outgoing 90ms exit so the page hero is the sole entrance owner. The outgoing route renders nothing while it exits (`ExitingRouteFrame` in `__root.tsx`): the router has already moved on, so its outlet would paint the next page, or the next article's skeleton, at the old scroll offset on top of the new screen. Its frame keeps the old page's height as a minimum, measured live by a ResizeObserver, so the scroll position never clamps and the footer never flashes up. The entering route shows its content only once the router's deepest match is its own path (the URL changes a frame or two earlier, and the outlet would still show the page being left), and it places its scroll position at that moment. The server-rendered route paints in its final state and plays no entrance, so its content is readable at first paint, before JavaScript arrives, and without JavaScript at all (`ServerRenderedRouteContext`); its below-the-fold scroll reveals park out of sight after hydration and keep revealing on scroll. Entrances play on client-side navigations. Editorial heroes measure lines from the loaded font: `document.fonts.ready` is read once per page load, so from the second page on the split runs before the frame paints and the hero never shows a blank frame. Blocks already on screen below a hero wait for its handoff (`HeroHandoffContext`), so a page lands top to bottom. Heroes follow document order: optional eyebrow copy enters from 14px below with opacity and no blur, the headline splits into rendered lines (measured with ordinary greedy wrapping, so headlines never use `text-pretty` or `text-balance`), reveals from `0.4em` below with a 4px one-shot blur on a 320ms visual spring with `0.1` bounce and strong ease-out opacity, then supporting metadata and actions use the same 14px opacity-and-transform follower entrance on a 240ms visual spring with `0.1` bounce and strong ease-out opacity. Lines stagger by 60ms, pause for 180ms, and followers stagger by 50ms, with follower delays capped at 600ms (`editorialFollowerMaxDelay`) so long lists never stretch the entrance. Once its line animations finish, the headline returns to plain text, so it reflows on rotation and resize instead of keeping the lines it was measured with. Each delay applies to both opacity and transform; `withDelay` in `StaggerReveal.tsx` passes it into the opacity sub-transition, which would otherwise start at once. On Home the stagger root is the whole `main`: after the hero, each section heading, list row, and the Stack list enter as followers, matching the one-time load cascade on the reference sites. Articles uses the same choreography for its hero only. The home introduction is the visual headline; Resume, Articles, and article titles remain the anchors on their routes. Same-path hash changes never remount the route boundary. The exiting desktop table of contents becomes inert and `display: none` immediately, then disposes after route commit.
- **Header continuity:** Article navigation transforms one persistent avatar (40px to 24px from a top-left origin) and the theme control between identity and breadcrumb geometry over 300ms on the route curve, with no layout projection or runtime measurement. Identity and breadcrumb text crossfade. Focus remains on the theme control, and identity-to-identity navigation does not retrigger the header.
- **Signature interaction:** The responsive table of contents receives the motion budget through Rare-style pointer-near dash magnification and an 80ms shared scroll pulse, plus mobile same-surface expansion. The mobile outside-click layer remains transparent; optional bounded drag is secondary to the menu’s content-measured morph. Keyboard, Escape, focus return, and reduced-motion paths stay direct and complete.
- **Restraint:** Repeated motion is limited to transforms and opacity; scale is reserved for small page-entry blocks and press feedback, the Articles route fades in once below its hero as one opacity-only tree, and complete article bodies never animate during scroll. Home section headings and rows enter once per visit as followers; every one is shorter than a viewport. Rows and chips confirm presses with `scale(0.985)` and `scale(0.97)` on `:active` over 160ms on `--ease-out` (`cubic-bezier(0.23, 1, 0.32, 1)`), disabled under reduced motion. Hover stays a plain background-color change because it fires many times per visit. The editorial hero's 4px blur is an explicit exception authorized only for headline lines during their one-shot mount entrance; supporting labels, descriptions, metadata, and actions travel 14px with opacity and no blur. The exception does not apply to article prose or route-sized trees. `prefers-reduced-motion: reduce` renders heroes immediately, snaps the header layout, removes entrance transforms, and keeps simple destinations instant. The ponds and the 404's sky are the only continuous animations (the footer garden moves only while growing in, for a few seconds after a touch, and for a few seconds when a breeze or a falling petal stirs it): the ponds' shared engine (53KB of lazy chunks, 20KB gzipped: the engine with its GPU renderer, fish and decor, plus the ripple simulation, and the WebGL helpers it shares with the footer garden) and the sky (a 21KB chunk of its own, 9KB gzipped) each load only after the page is idle, render only while on screen in a foreground tab, cap resolution (fish and sky 2x, water 1.5x), and have an always-present Pause/Play control. Under reduced motion a scene starts paused on a settled still frame, clicks fast-forward or swap still frames instead of animating, and Play is an explicit opt-in.

## 6. Do's and Don'ts

### Do:
- **Do** keep every primary surface within the narrow reading column.
- **Do** use semantic theme tokens and test both explicit `data-theme` values.
- **Do** preserve accessible focus, reduced-motion, and overflow safeguards.
- **Do** publish guides through validated series or topic frontmatter rather than route-level title inference.
- **Do** let evidence, writing, and code carry the visual weight.
- **Do** use `SectionHeading`, `.hover-row`, `.chip-link`, and `.text-link` instead of one-off label and link styles.

### Don't:
- **Don't** reintroduce a serif display system, oversized clamp-based headings, or magazine layouts.
- **Don't** add a second accent color, gradients, glass, shadows, or image tiles to the home page.
- **Don't** bring back uppercase mono section labels or terracotta link underlines.
- **Don't** hardcode guide metadata in route components.
- **Don't** let React render guide prose; interactive pieces go through the island registry.
- **Don't** override Expressive Code fenced-block styles with legacy `pre` rules.
- **Don't** use motion as decoration; respect reduced-motion preferences.
